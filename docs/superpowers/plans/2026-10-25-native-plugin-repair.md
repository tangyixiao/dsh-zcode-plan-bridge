# ZCode 原生插件接入修复

目标：沿用用户已确认的插件安装、无限重试、可调间隔及 DSH 可选接入要求，修复主聊天没有加载重试模块的问题。用户已明确要求继续实现，撤销外部启动器方案。

方案：普通插件不支持 settings/environment 注入父 Agent。插件的 MCP 子进程启动后，只识别自己的直接父进程；核对它是本机 ZCode Desktop 的 app-server，再通过短时本地 Node 调试连接，在该 Agent 的内存中包装模型 transport resolver，覆盖已经缓存的原传输。同步处理等待重试期间的原生流空闲计时，提交输出后在模型事件迭代器恢复保护。成功或失败后关闭调试连接和端口。不会修改 ZCode 程序文件、启动命令、全局环境或会话数据。这是依赖内部接口的非官方兼容方式。

安装与开关仍由 ZCode 插件管理负责。插件配置通过 userConfig 显示间隔秒数；MCP 配置工具提供状态和调整。当前支持用户范围配置。禁用或卸载插件时撤销内存包装并停止社区重试；MCP 发现辅助进程正常退出后，已注册且启用的插件继续工作。未注册测试运行时才由辅助进程租约负责生命周期。检测到已有调试服务时不抢占；目标 PID、入口或运行能力不匹配时拒绝加载。DSH 继续沿用其显式开关和原加载器，不自动附加其他 Agent。

- [x] 实现父进程身份校验、串行短时调试连接和内存安装/撤销；覆盖错误 PID、端口占用、重复加载、插件关闭和取消。
- [x] 增加插件间隔设置和状态；通过 ZCode 自带管理更新本机缓存到 0.3.0、用户范围启用；隔离真实 Desktop Agent 验证普通插件加载。用户现有桌面聊天仍须新建/正常重开后核验，不宣称真实账号 UI 验收。
- [x] 回归 CLI/DSH 核心，打包可安装插件，更新文档；104/104 测试及 typecheck 通过，DSH Desktop 配置保留且依赖更新 0.6.0-community.2。GitHub 延续原草稿 PR，不合并或发布 npm。

主聊天的 transient 请求必须一直留在社区 transport 内，直到成功或取消；余额/鉴权等终止错误直接返回；输出提交后不重放。插件内原生接入只承诺无限模式，有限模式保留给显式 CLI/DSH 加载器，避免与原生已初始化的计数重叠。
