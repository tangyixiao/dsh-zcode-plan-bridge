# ZCode 社区自动重试插件与 DSH 可选接入

日期：2026-10-25。状态：用户已确认总体方案；本文等待书面设计审阅。本文描述待实现行为，不代表功能已经可用。

## 目标与交付物

用户需要一个独立于 DSH 的 ZCode 社区自动重试插件，并让现有 dsh-zcode-plan-bridge 可以选择启用它。采用用户确认的“社区插件＋配套运行时加载器”方案。

交付物包括可安装的社区插件包、独立的运行时加载器、桌面启动入口和恢复说明，以及桥接插件的配置开关、诊断、测试与安装包。社区组件使用独立身份 zcode-community-retry，明确标注非官方。首版支持当前 Windows 本地环境；其他系统不宣称经过验证。

## 已核实的基础与实现前验证

- ZCode 普通 Hook 没有模型请求失败事件。Stop Hook 的继续机制不能作为模型请求自动重试实现。
- MCP Apps 的主会话 sendMessage 在没有用户操作时需要确认，不能作为后台自动恢复通道。
- 本机 ZCode app.asar 包含 ZCODE_AGENT_SERVER_COMMAND 和 ZCODE_AGENT_SERVER_ARGS_JSON；官方进程管理源码支持通过它们指定 Agent 启动命令。
- 现有桥接在 lib/app-server.js 集中启动 CLI，适合选择加载器或原 CLI；账号准备、模型目录、会话复用仍由现有模块处理。
- 自定义命令入口存在，只证明有候选接入路径。全局 fetch 包装是否覆盖当前桌面和 npm CLI 的实际模型传输，以及如何准确关闭原生重试，必须先通过隔离进程验证。验证失败时报告不兼容，不改程序包或扩大拦截范围。

## 组件与数据流

### 独立社区插件

插件提供配置、状态查询和使用说明，通过普通 ZCode 插件清单与社区市场清单分发。持久配置和诊断状态写入插件数据目录，安装目录保持只读。插件状态区分“已安装”“加载器已启用”“当前 Agent 已加载”“实测通过”。仅安装或打开市场开关，不能报告原生模型请求已受保护。

插件本身不发送“继续”消息，不接管其他插件的工具，不通过 Stop Hook 假装捕获模型错误。

### 配套运行时加载器

桌面配套启动入口为本次启动的 ZCode 进程设置自定义 Agent 命令。命令加载社区传输层后执行原 ZCode CLI。原应用继续拥有账号、授权、模型选择、会话、工具执行和上下文。

加载器启动时核对 Node 能力、CLI 文件与传输接入能力，输出可诊断的版本标识。拦截范围仅包含经识别的模型推理请求。鉴权、额度查询、插件下载和其他网络请求直接交给原传输。

启用入口不修改系统全局环境变量，不覆盖 app.asar 或原 CLI，不写入明文凭据。首次启用需要退出已有 ZCode 实例，再从配套入口启动；已有实例可能接管新窗口，诊断必须识别“仍在旧进程”并提示。任务运行期间不自动退出应用或重启 Agent。

恢复方式是退出配套实例，使用原启动入口启动。更新后如果 CLI 不兼容，明确返回加载失败；不能静默退回原 CLI 却显示重试开启。

### 共享重试模块

桌面加载器和 DSH 使用同一版本的重试模块。请求从原模型传输进入模块，经错误分类、预算与取消检查后继续请求；最终响应交回原运行时。模块不重新提交整个会话，不重放工具执行。

可重放请求必须有可重复读取、大小受限的请求体。无法安全复制的流式请求体直接返回原结果，不尝试重放。首版请求体复制上限为 16 MiB；超过限制时状态明确记录跳过原因，正文不落盘。

### DSH 桥接

新增 communityRetry.enabled，默认 false。关闭时保持现有启动与重试行为；开启时使用配套加载器，并显式传入共享配置和实际 CLI 路径。诊断显示模块版本、是否在子进程生效及启用失败原因。

开启后，社区模块统一管理模型请求的额外重试次数，关闭该子进程的原生模型自动重试及桥接对同一次请求的外层重试。每层的关闭必须有测试证据，避免 6 次配置变成多层次数相乘。会话锁恢复等不同用途的处理保持独立，不能把失败的模型回合整体重新发送。

开关变更只在空闲后或下一次创建子进程时生效。运行中的回合继续使用启动时的配置快照，不中断切换。

## 重试策略

默认最多额外重试 6 次，总计最多 7 次物理请求；默认等待基数 5 秒，指数因子 2，本地等待上限 60 秒，并加入抖动。总恢复预算为 10 分钟，从初次模型请求开始计时；DSH 调用方的取消或更短超时始终优先。

服务端 Retry-After 支持秒数、HTTP 日期和 retry-after-ms。有效值最多接受 5 分钟；若等待会超出剩余预算，则结束并返回原始失败。x-should-retry 明确为 false 或 0 时停止重试。不同字段冲突时先执行终止规则，再决定等待时间。

允许重试：明确的 user/model concurrency limit exceeded、短暂连接失败、请求超时、HTTP 408/429/500/502/503/504，以及已确认属于瞬时错误的 ZCode 上游业务码。普通 403 或未知业务错误不凭模糊文案自动重试。

终止规则优先于 HTTP 状态：用户取消、1113 余额或资源包错误、认证失败、模型无权限、套餐到期、长期额度限制、非法请求均直接结束。重试不承诺绕过服务端并发或配额限制。

## 流式边界与取消

仅在尚未交付有效模型输出时重试。有效输出包括推理内容、文本和工具调用；元信息、心跳及可识别的空开始事件不算有效输出。

SSE 在有限缓冲内识别首个有效事件或明确错误，支持分块、CRLF、多行 data、UTF-8 跨块和 HTTP 200 内的业务错误。探测缓存上限为 256 KiB；达到上限或遇到无法可靠识别的内容时交付原始流并关闭该请求的重放资格。首字节及探测超时使用有限截止时间，不额外无限等待。

一旦交付有效输出，后续流中断保留原错误，不自动重新执行该请求。重试前先终止和清理上一响应；清理在有限时间内完成，不能挂住下一次尝试。

每个逻辑请求只存在一个重试循环。AbortSignal 贯穿网络请求、流探测、清理和退避等待；取消后不得启动下一次请求，不得发送会话继续消息。应用退出时释放计时器和流，插件不创建常驻守护进程。

## 状态与隐私

诊断状态包括启用状态、运行时版本、尝试次数、等待截止时间、错误类别、最终结果及跳过原因。状态发布使用独立诊断通道，不能向 app-server 的协议 stdout 写调试日志。

日志只记录安全元数据，不记录访问令牌、请求头、提示词、会话正文或完整响应。保留原服务端错误与请求标识时经过字段筛选。桌面插件只承诺自身状态查询；在实际验证前，不承诺原生聊天底部会显示自定义重试提示。

## 验收证据

1. 用本地可控上游验证连续失败两次后成功，物理请求恰好三次；重试耗尽恰好七次，原错误可见。
2. 验证并发错误、HTTP 429、Retry-After、HTTP 200 SSE 业务错误和网络超时；验证 1113、认证失败、长期额度限制及显式禁止重试只有一次请求。
3. 验证等待中取消、请求中取消、流探测中取消及退出，均无后续请求、残留计时器或子进程。
4. 验证首个文本、推理或工具调用之后的断流不重放；异常分块、缓存上限和不可复制请求体均保守交回原流程。
5. 验证原生重试与 DSH 外层重试没有叠加；并行逻辑请求各有预算，一个请求不会触发两个恢复循环。
6. 用真实 ZCode CLI 和真实加载器连接可控上游完成协议测试，证明模型请求实际经过重试模块。只测独立函数不算运行时接入通过。
7. 桌面实际启动验证加载器状态、模型列表、简单对话、停止、退出及原入口恢复；DSH 分别验证开关关闭、开启和不兼容诊断。涉及重启时先确认已有任务已结束。
8. 真实账号只做有界短请求，保留结果；短请求成功不能替代长任务验收，也不能证明真实上游的所有限流场景已复现。
9. 保留桥接既有测试、类型检查和 diff 检查；产出安装包、校验值、配置示例、已验证版本和未验证项。GitHub 代码上传与本机安装验收分别记录，不发布 npm 或合并 PR。
